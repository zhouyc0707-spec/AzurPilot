# 心智扫描的有限退出与正确性验证

## 调用链与范围

沿计算器页面的 `config.patch` → `tasks.run(MindCalculatorScan)` → `alas.py` →
`MindCalculatorScan.run/_scan_pages` → `recognize_cards/ScanMerger/ScanPolicy` → 事务保存核对实现。
上传截图共用识别器；`FleetScan` 是独立任务。共享资料使用 `assets/ship/ship_data.json`。

## 编队、排序与继续扫描

- 编队编号先复用 `FleetScanner` 的绿通道模板；未命中时补读 RGB 三通道均达阈值的白色字形，
  使用同一编号模板及相似度。只有编号或“编队”文字证据可认定编队，不凭蓝色背景或排序猜测。
  比较全部编号候选，最高分达到原门槛且领先次高分至少 0.05；两种字图的数字冲突时保留未知，不按模板排列顺序选择首个过线编号。
- 局部名称、等级、编队或排序疑点在合并前最多三次稳定新帧复核。心智扫描等级三次仍失败则终止并保留旧完整结果；累计跨页冲突留下未确认等级时，提交前也拒绝保存。心智截图入口遇到未知等级整张拒绝导入。
  等级可靠但名称、编队或排序仍有疑点时，保留独立待核对船位并继续；新 `FleetTechScan` 单独允许未知等级为 `level=0, review=true` 的证据，不计费、不确认缺失。
  旧清单/文件导入的未知等级仍可人工核对；待核对项不能按候选名称合并或按候选等级静默丢弃。
  身份三帧仍未确认时显示实际 OCR 读数，保留累计行列与最终原帧；显示读数不等于确认身份，待核对卡位独立保留且不计费。
- 后续页核验本页与前一船位的边界，避免已接受的旧疑点引起每页反复重读。早停始终检查全部累计船位。
  排序状态由当前证据重新推导；未纠正的等级、编队或排序疑点仍要求扫到底，不因翻页恢复早停。
  只有同一物理船位的新帧补齐证据后才可能恢复；原人工核对标记继续保留。
- 早停必须有完整三行七列，全部为普通舰、等级可靠且低于下限，累计编队段和普通段分别降序。
  边界包含上下限；高于上限仍继续扫描。

## 有限退出与保存

- 所有截图循环分支都检查稳定等待期限，持续动画、页面丢失或反复弹窗超过 30 秒终止并保留旧清单。
  无进展检查在循环前部；定位最多八次拖动，保留卡位与页数上限。
- 实际位移来自相邻稳定截图的唯一重叠；中间帧累计位移，整页按三排推进。反向或过冲也须核验。
  触控距离、缺卡或通用滚动百分比容差均不能证明到底；末页仅在滚动条实际像素端点确认后结束。
- 心智和科技扫描均按连续的颜色匹配像素确认滑块，不使用通用 `appear()` 的 10% 长度门槛。大型船坞的短滑块有效；像素缺失或断裂时保留旧记录，不能猜测已到底。
- 局部疑点随完整结果一次保存。停止、布局/位移/设备/模型异常均不保存半份结果。
  保存仍在配置事务内重读并比较 revision，拒绝覆盖用户并发修改。
  只有事务提交成功后清理该实例上一轮生成的诊断图与 JSON，本轮原帧继续保留；停止或异常不清理旧结果证据。
  待核对行允许校正基础稀有度，编辑后仍待核对，人工选择计入后才计费。
- 名称、等级、基础稀有度均确认的结果直接计费；原舰/改造取最高等级，同级优先改造，II/META 独立。
  布里、联动、μ 兵装和幼体按共享资料排除，不能因性能优化改变身份或费用规则。

## 诊断与性能边界

自动扫描与上传的识别器关闭逐字图诊断 I/O；其他 `AlOcr` 调用沿用默认设置。
稳定比较保留完整签名与原阈值，位移计算保留原采样、全部候选及歧义阈值。
需要字图时显式传入 `AlOcr(..., save_debug_images=True)`，不改共享模型缓存。

日志中的“心智扫描源码”包含模块路径与 SHA-256；“本页识别摘要”包含舰船字段、编队和等级可靠性。
“早停检查”给出拒绝理由，底部退出记录实际像素端点。核对原帧写入日志目录的 `mind_scan/<实例>/`，
写盘失败仅记录警告，不影响有界复核。跨页疑点的来源应指向包含该船位的原帧。
核对位置采用累计网格行号，不采用合法停位时会波动的原始像素值；置顶编队页与局部复核页同时保留最终卡位 JSON。
已确认舰名的持久提示描述名单身份，实际复读候选为诊断字段 `name_reads`；不能把 OCR 读取路径或标点当成身份变化。
名称图像右端的同基线独立双点可证明截断，精确路径先按目录唯一补全。
精确与有限复读失败后，由 `mind_name.match_lua_name()` 对照共享 Lua 国服目录做相似度补全；
四字以上读数或明确省略号允许按可见长度比较长名前缀，前缀形近字也参与匹配，不能用缺失尾部惩罚匹配分；
多轮至少两次支持同一候选，低于 0.55 保留实际 OCR 原文待核对。
最高分附近 0.05 内的候选用已识别的稀有度、橙色 META 卡框外沿、航母白色图标区分；
图像只筛选候选，计费基础稀有度和排除分类仍取目录。飞机字形由正航/轻航/航战/潜母共用，不能据此细分；
改造别名沿用基础舰种时，不能据战列基础舰种排除改造后的航战。META 外沿与普通舰精确命中冲突时也需复读，防止截断前缀被直接当成普通舰。
明确身份冲突、未确认 II/META 后缀以及无图像证据的同分身份仍须核对；不修改公共 `find_ship()` 或 `ShipNameMatcher` 的严格查询。
短名失败时可追加原色文字行两侧各去六像素后的双读，两次须分别精确确认同一身份；长名、截断名和 II 家族不走这条路径。
单字名失败时，在共享黑白字图下移 0/2/4 像素、两侧各去 4/8 像素的六个组合中平滑放大双读；至少一组的两种尺度都精确确认同一身份，各组不得出现其他身份。不能用跨组分散的单次命中代替双读，也不能将形近字设为任意别名。
已授权诊断可临时创建 `cache/mind-scan-diagnostics` 保留全部接受页并暂停旧图回收；结束后移除。它只增加诊断 I/O，不能用其耗时宣称默认性能。

## 验证入口

定向回归：`uv run python -m unittest tests.test_mind_calculator tests.test_mind_scan tests.test_mind_scan_stuck`。
真实故障夹具 `mind_dock_stuck.png` 已隐藏顶部容量；蓝卡反例为 `mind_fleet_blue.png`。
`mind_fleet_six.png` 回放同一 6 编队徽标的两种采样相位，验证首个过线候选不能抢先返回。
`mind_names_stuck.png / json` 回放白凤形近字与长名省略号漏读，完整名称条反例不能产生截断证据。
`mind_yorktown_phase.png` 回放实际 II 后缀被裁成 I 的采样相位；不能因另一次漏读后缀而接受基础型。

`mind_matsubream_phase.png` 覆盖短名被卡框读成额外字母的真实相位；不能通过直接删除 OCR 字符获得匹配。
`mind_shizuku_phase.png` 覆盖单字名细笔画相位变化；一次命中或补读冲突仍须待核对。
`mind_ryujo_phase.png` 覆盖实图核实的龙骥→龙骧字面误读；`mind_retrofit_punctuation.png` 覆盖华甲改造目录的两种标点别名，只统一已确认身份，不能消除普通/改造冲突或修改共享资料。
`mind_rarity_phase.png` 覆盖同一紫框 SR/R 颜色条件重叠；卡框分类前剔除重复蓝色计数，不降低阈值，并验证真实普通蓝框不变。
`tests.test_mind_lua_names` 与 `mind_lua_names.png/json` 回放五张真实待核对卡片，覆盖长名缺尾、普通舰/META 共用截断前缀、形近字及同稀有度幼体的舰种区分。
“小天凤”必须结合航空图标确认“小大凤”；不能只凭名字或紫框选择“小天城”。模板来源见 `assets/ship/dock_aircraft_icon.md`。
`mind_lala_truncated.png` 回放“拉菈·撒塔琳·…”的截断与形近字并存读数，正确补全“菈菈·撒塔琳·戴比路克”，保留联动排除及范围语义。
同一回放验证未知等级仍不计费、META 身份独立、幼体自动排除；整页对照须确认原本已识别的卡片未被改写。
退出回归使用真实 `ScanPolicy`、`ScanMerger`、真实 `Timer` 和虚拟单调时钟，不能将 `can_stop` 固定为 True。
虚拟时间和 `ImmediateTimer` 的测试耗时均不代表实机性能。

共享 OCR 改动检查 `tests.test_ocr_settings`、`tests.test_ocr_rpc_recovery`；关联舰队检查
`tests.test_fleet_ship_names`、`tests.test_fleet_emotion`，异常恢复检查 `tests.test_scheduler_recovery`。
前端变化验证清单单元测试、typecheck、构建及 `playwright.mind.config.ts` 浏览器流程。

实机按用户指定实例与范围执行；改文件前确认工作进程已退出。新 Windows spawn 工作进程重新导入磁盘源码，
以其源码日志、工作进程登记和模块摘要核实版本。服务重载前核对部署 Run、显式 --run、记忆运行与 reloadalas，
防止其他实例自启。多轮验收比较完整业务字段、顺序、状态、费用及来源提示；诊断路径等允许差异须由用户明确界定。
首次发现差异即停止后续扫描，保留当次证据；更新版本后重新建立连续成功轮次。
