## 自动合并后的必要修正

### 配置移动不能覆盖旧设置

运行器虽有迁移，WebUI 原先只补新默认值。若先在页面保存其他设置、再启动运行器，新默认可能掩盖旧 `SkipStrategicSearchCheck=true`。现 `ConfigService` 的只读合并也迁移两个移动字段，新显式值优先；只读不写盘，事务保存时才持久化。旧海里 `true/false` 保持迁移为 `0/-1`，已有数值不重置。

### 独立海里数不能在旧版画成行动力零点

旧版 React `_ap_panel()` 与原 PyWebIO `_normalize_ap_chart_points()` 都曾在缺少 `ap_total` 时回落到 `ap` 或 0。新上游会产生纯海里数记录，因此同步修正两条展示路径：体力及资产只使用完整实测总量，排除旧 `hazard1_estimate`；真实总量 0 仍显示，海里数保留独立原序列。原始历史不删除、不改写。混合历史回归同时覆盖完整总量、当前量、海里数、推算及真实零值。

### 迟到后台观察同时保护内存和磁盘

上游仅在磁盘事务与数据库层拒绝较旧观察，内存仪表盘及黄币预算缓存仍可能先回退。现按资源比较已加载及待保存的最新采样时间，在更新内存、预算和低币状态之前验收；相同时间可合并，一项过期不阻止同帧其他资源。旧低币结果清除后重新采样，不触发错误补币。磁盘仍由事务独立校验，不为主循环新增同步文件读取。

本次上游改动的前端产品文件与新上游一致。旧版统计组件、主题样式及本地评分／锁定入口保持原实现；只有旧版后端曲线按用户已确认的实测口径适配。
