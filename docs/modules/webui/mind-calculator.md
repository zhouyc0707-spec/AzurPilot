# 养成计算与船坞识别

当前入口为「舰队管理 → 舰船数据 → 养成计算」，地址 `/i/:instance/task/FleetAnalysis?tab=mind`。旧 `/i/:instance/mind-calculator` 和 `/i/:instance/task/MindCalculator` 链接自动跳转到此页签。所有主题使用同一新流程，保留旧版主题外壳和喵语。页面行为、存储和接口以 [舰船数据](fleet-analysis.md) 为准。

## 计算与数据

页面读取已确认的逐卡舰船及独立累计科技记录，每个有科技奖励的舰种选择当前最高等级副本，计算升至120级的剩余心智单元与物资。已完成120级科技或当前副本已到120级的舰种不重复计算；身份待核对及无科技奖励舰种不进入自动范围。计算使用实际等级和固定觉醒边界，不估算经验，不保存独立试算清单。

`mind.plan` 按正式数据版本及副本 ID 只读计算，接口支持120或125级目标。费用规则来自 `assets/ship/cultivation.json`，实现位于 `module/runtime/fleet_cultivation.py`。按舰种排除的计算偏好保存在浏览器，不写入舰船或科技记录。

舰船修改通过 `dock.patch` 保存。`mind.import` 解析 JSON、CSV、XLSX，`mind.recognize` 识别 PNG、JPEG、WebP；两者只返回可核对记录；截图识别仍严格拒绝无法确认的等级。随后通过 `dock.stageImport` 暂存并由 `dock.review` 确认。文件和截图保留独立副本。`mind.catalog` 和 `fleetTech.catalog` 提供公共资料。

## 共享扫描

`alas.py::dock_scan()` 派发唯一的 `DockScan` 游戏任务，实现在 `module/retire/dock_scan.py`。扫描重置筛选、确认搜索关闭并回到船坞顶部，再按三排推进。`module/runtime/mind_recognition.py` 负责卡片定位、船名与等级复读、相邻截图位移核验和跨屏去重。

`ScanMerger` 使用重叠区域确认实际滚动距离，再按绝对位置合并同一卡片；中间截图可累计位移，两次整页识别相隔三排时无需直接重叠。确认数据按物理副本存储，不在扫描阶段按舰名或最高等级合并。

图鉴通过 `group_type` 区分同名身份。天城、加贺的不同舰种需名称复读及飞机／炮舰图标等正向证据，不按稀有度或缺失图标猜测。约克、新月等同名同舰种默认保留独立待核对卡位。改造与原舰共用基础身份，II型与META保持独立身份；陌生读数不推测改造关系。

本地严格等级保护继续作用于新的 `DockScan`：同一卡位最多三次新帧仍无法确认等级，或累计跨页等级冲突未解决时，终止读取并保留旧完整数据，不以 `level=0` 提交自动扫描结果。历史或人工未知等级仍可展示为待核对，不推算费用。名称、编队或排序疑点保留原卡位及必要交界核对记录，之后完整可靠且已越过范围下限的普通舰页面可恢复早停；当前页存在疑点、缺格或仍未越过下限时不能早停。持续动画或页面丢失超过30秒、回顶或三排定位无法确认时，以 `MindCalculatorScanError` 结束任务，保留已确认数据。

完整性需同时满足全等级范围、筛选清空、到达底部、物理卡数与船坞数量一致且没有未确认卡位。仅完整读取可建议移除缺失副本。扫描只生成待确认差异；未处理候选阻止下一轮读取，异常、停止和版本冲突不会覆盖正式数据。

## 本地扫描安全保护

- 等级使用独立原生字形及交叉复读，不猜补百位。仅失败卡片且已确定 Lv 锚点与数字位数时补读完整等级条，两次均须有明确 Lv 前缀、等级一致且位数吻合，不覆盖已有有效冲突候选。
- 按连续颜色像素识别短滑块，不套用通用控件10%长度门槛；阈值边界一行仅以二维八邻接和相邻严格颜色核验抗锯齿像素，不扩张端点。滑块不可靠时不能据此证明到底。
- 滚动位移必须有唯一图像证据，双端运动和已核实手势只约束候选，不能直接使用触控距离或降低图像阈值。同名同级重复画面不等于零位移。
- `ScrollAmbiguityError` 时保留上一确认位置、累计位移及卡位，不追加拖拽，最多使用三张稳定新帧原位复核；保存前后原帧、评分和候选位移，成功后才推进。持续失败或超时保留旧完整数据，识别失败不以重启模拟器掩盖。
- 扫描使用实例现有识别配置；用户主动上传截图使用本地 ONNX/CPU，不读取私人云配置。正常字图关闭逐字调试写盘，显式诊断仍可开启，错误现场及有限复读证据保留。
- 相关离线回归包括 `tests.test_mind_scan_scroll_recovery`、`tests.test_mind_scan_stuck`、等级与舰名实图夹具；历史故障尾帧可核验已知纹理，不能替代缺失的失败配准对，也不能证明所有真实游戏场景。

## 旧数据导入

2026-10-28 用户明确选择接受上游新流程：旧记录只留存备查，不保留原排除与导出行为；不将旧 `excluded` 标记解释为新版计算偏好。

唯一保留的迁移入口是 `dock.importLegacy`：显式读取本实例旧 JSON，经 `module/runtime/fleet_legacy.py` 转换后暂存为新版舰船与科技候选，确认后写入 SQLite。原 JSON 保留，日常读取不自动加载旧字段；旧 SQLite 版本不自动升级。

历史实机证据见 [2026-10-14 扫描验证记录](mind-scan-verification.md)，其中旧页面与计费结果只描述当时版本。
