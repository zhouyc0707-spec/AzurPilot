# 心智单元计算器

> 在 AP 内扫描船坞、核对舰船清单，并计算升至 120 级所需的心智单元Ⅰ与物资。

## 1. 模块概述

实例侧栏的「心智单元计算器」打开 `/i/:instance/mind-calculator`。
用户可以手工录入、导入 JSON / CSV / Excel、导入船坞截图，或运行 `MindCalculatorScan` 自动任务。
识别得到的舰船全部进入待核对状态，确认后才纳入费用计算。

实现参考心智单元计算器 v0.32.43 还原工程的 `Calculator.cs`、`OcrService.cs` 和 `AutoScanService.cs`，
在 Python / React 中独立实现，并复用 AP 的设备、OCR、船坞导航和任务恢复机制。
公共舰船资料由原工具的 Wiki 缓存提取，保留来源与更新时间，不包含原工具私人配置。

## 2. 模块职责

### 负责

- 按实例保存舰船清单、核对状态、排除状态与数据版本。
- 定位船坞卡片，重读船名及等级，按跨屏位置合并卡片。
- 按基础稀有度计算剩余觉醒材料，按基础舰船身份取最高等级。
- 提供五种界面语言、核对编辑、筛选分页及文件导入导出。

### 不负责

不执行觉醒、强化或退役，不推算升级经验，不统计 120→125 级的心智单元Ⅱ。
不调用原 WPF / WebView2 程序，不接入原工具的云 OCR 或同步账号。

## 5. 核心组件

`Card` 包含列、屏幕坐标、可编辑舰船字段及识别质量。
`ScanMerger` 从相邻截图的重叠区域核验正负滚动距离，映射绝对行坐标后按位置选择较好的读数。
拖动期间每帧通过 `advance()` 累计位移；两次整页 OCR 相隔三排时，不要求这两张截图直接重叠。
同名同级的不同位置不会在扫描阶段被删除；最高等级归并属于后续计算阶段。

舰船字段为 `name / level / rarity / base_rarity / excluded / review / source`。
等级 0 表示未读到，不计费。`source` 保留截图文件名、扫描页与识别提示。
`revision` 是保存的舰船数组的 SHA-256，用来拒绝过期覆盖。

## 6. 工作流程

手工录入或文件导入 → 草稿计算 → 核对与修正 → 保存 → 导出。

自动任务：导航至 `page_dock` → 重置筛选 → 滚动条回顶并确认 → 持续截图等待画面稳定 →
识别三排卡片并核验标准行距 → 设置下一组三排目标 → 持续按住滚动条并逐帧计算位移 →
目标位置稳定后读取整页 → 确认滚动条到底 → 比较旧数据版本 → 保存结果。
任务不使用固定休眠判断游戏界面是否就绪。

每页推进三排，采用船坞 `CARD_GRIDS` 的 227 px 行距，三排累计 681 px。
首屏检测到的相邻行距须与标准行距相差不超过 3 px；卡框圆角与稀有度产生的色带起点偏差不参与累计目标。
右侧黄色滑块通过后台 `glide()` 逐像素连续移动，触点保持按下，截图和识别在主线程并行进行。
每次新抓取滑块从 4 px/s 起步；倍率未知时只探测一像素，仅在截图确认实际位移后按 1.5 倍逐步加速。
已知倍率后将卡面速度限制为 600 px/s，接近目标按剩余距离减速；触点发送步长始终为一像素，不随截图帧率跳跃。
每张新截图立即核验重叠位移，边拖边累计位置，
不先松手或等画面停稳再计算。滑块较小时仍按颜色像素识别，不采用通用 `Scroll.appear()` 的 10% 长度门槛。
顶部滑块可能超出通用按钮框，抓取中心包含框上方连续的黄色像素，避免截断后抓错中心。
回顶在持续触控下越过滑块中心的顶部极限，确认夹紧后再建立绝对坐标，避免接近顶部就开扫。
实时测量滑块与卡面的位移倍率；接近目标而一像素滑块不足以精确定位时，切换到卡面持续触控校正。
接近三排目标时，还用至少两排具有标准间距的卡头校准行内位置，修正逐帧整数位移累积的取整误差，再精调至三排对齐。
卡头只校准已追踪的绝对位置，不能代替跨页重叠证据。快拖丢失重叠时保持抓取，回到最后已确认的触点坐标，
平滑回退恢复重叠证据后，以实际测得位置减速继续扫描；三秒与连续截图计数均达到阈值仍无法确认时退出，不提交本次结果。
抓住滑块后，仍按住的触点横向移至左侧 64 px，跨过拖动阈值，并避开会遮住黄色滑块的游戏触控菱形；
拖动由原滑块捕获，横向移动不改变纵向位置。按下特效残留时持续截图，一秒与连续截图计数均达到阈值仍未见完整滑块则退出，期间不继续移动或猜测位置。
卡面触点先横移 20 px 再返回，跨过拖动阈值；此后的纵向微调和反向校正保持同一触点，不反复松手重发短拖动。
累计坐标接近全局三排目标一像素内时先停止后台移动，保持按下继续核验画面；
位置漂移则继续校正，稳定按住 0.4 秒后才松手，画面稳定 0.6 秒且通过连续截图确认后才做整页 OCR。
黄色滑块到达轨道底端即读取末页并结束，可提前结束当前三排目标。末页允许剩余舰船不足三排。
单页最多 1024 次逐帧移动；已核实的实际位移重置设备卡死计时与连击历史，无进展继续沿用设备卡死检测与扫描超时。
实时触控支持 MaaTouch、minitouch、uiautomator2、scrcpy、nemu_ipc；其他后端明确提示更换控制方式，不回退为滑动或点击。

识别先检测与七列卡框边缘对齐的稀有度色带，并结合整屏 `Lv` 文字锚点定位行。
有色框证据的行独立保留，即使整屏 OCR 只检测到其他行的等级，也会逐卡重读该行的船名与等级。
扫描范围包含第三排完整船名条，卡面内部的灰色长条不能作为额外一排。
逐卡裁剪船名条与等级条；船名使用白字、META 粉字预处理，未匹配名称再用放大原图、放大字图和整屏文字重读。
等级使用原色、两倍白字及三倍白字重读，以像素数字位数约束候选，不直接猜补百位。
资料匹配结合可识别的卡框颜色；模糊候选需要唯一，并保留校正提示。
有卡头或等级证据但名字未读出的卡片使用占位名称保留，要求人工修正。

## 7. 调用关系

### 上游

React 页面经 `/api/v1/ws` 请求 API；手动工具任务经运行时调用 `alas` 方法。

### 下游

使用 `Dock` 导航、筛选及 `DOCK_SCROLL`，使用设备截图和 `live_drag()` 连续触控接口。
使用 `AlOcr` 的 PP-OCRv6、等级识别接口和现有 OCR 工作队列，不另建模型下载系统。
Excel 由锁定的 `openpyxl` 依赖读写。

## 8. 数据流

截图 → 内存卡片与位移 → 可编辑舰船数组 → 实例配置 → 费用报表 → 浏览器或导出文件。
自动扫描不保存整屏截图、OCR 模型或设备配置到舰船资料中。
未知名称可手工指定基础稀有度；已知舰船的基础稀有度由资料确定。

## 9. 状态模型

每行计算状态为 `included / merged / review / excluded`。
排除优先于核对；待核对、未读到等级或缺少基础稀有度时不计费。
同基础身份只保留有效清单中最高等级的一行，其余行标为合并。
META 保留独立身份；μ兵装与幼体舰船自动排除。

## 10. 配置

`MindCalculatorScan.MindCalculator.Result` 是隐藏的 `stored` 配置，默认 `{}`，
内容为 `ships` 和 `updated_at`。仅保存本实例数据，配置生成器维护对应模板与类型。
自动任务使用实例现有 OCR 配置；上传截图接口使用默认 ONNX / CPU 设置，不读取私人云配置。

## 11. 异常与错误处理

输入文件、分辨率或字段错误返回 `INVALID_PARAMS`；旧版本保存返回 `CONFLICT`。
船坞无法回顶、卡片无法定位、相邻截图无法对齐或三排定位不确定时抛出 `MindCalculatorScanError`。
任务运行器记录具体原因、完整异常与错误截图，结束本次工具任务并保留旧清单；识别失败不触发模拟器重启。
画面长时间不再滚动或达到页数上限但未确认到底时抛出 `GameStuckError`，沿用上层恢复。
停止任务、设备异常及 OCR 异常不提交半份扫描结果。

## 12. 并发与线程模型

API 业务沿用 WebSocket 工作线程，OCR 沿用现有队列。
API 保存和游戏工作进程共用实例配置事务锁，锁内重读并比较舰船版本。
扫描途中用户保存不同舰船数据时，任务拒绝覆盖并提示重新扫描。

## 13. 缓存与持久化

公共资料按进程缓存；文件更新后重启服务加载。
舰船清单原子写入实例配置；原工具私人配置和用户下载路径不会进入内置资源。
前端将未保存草稿与原版本存入按实例区分的 `sessionStorage`，重载或导航后可恢复。
恢复的过期草稿仍受保存版本校验；重新载入会明确丢弃草稿。

## 14. 生命周期

计算器页面加载公共资料与本实例清单，编辑后防抖计算，每五秒读取保存结果。
有未保存草稿时轮询不覆盖编辑。实例路由切换重新挂载页面，响应不会写入其他实例。
自动任务仅在用户启动时连接设备，确认完成后一次保存，停止操作复用任务运行器。

「自动扫描船坞」要求连接可用、数据已加载、草稿已保存，且当前实例没有任务运行或更新。
禁用时按钮下方直接显示当前阻塞原因，扫描期间提供「停止扫描」。
游戏地区使用实例列表中的 `region`，由后端按 `Emulator.PackageName` 和现有 `to_server()` 规则解析。
`Emulator.ServerName` 是可关闭的开服检测配置，不能用来判断是否国服。
包名为 `auto` 时地区暂为 `null`，允许启动，由设备检测实际包名后执行任务中的国服校验。

## 15. 扩展方式

更新资料时保留 `source / updated_at / ships`，验证基础稀有度和身份归并。
支持其他游戏服务器前，应增加对应语言舰船资料与截图回归；不能只解除国服检查。
调整 API 参数时重新生成契约；调整配置源时重新运行配置生成器并补齐五语言文案。

## 16. 修改注意事项

费用阶梯按已越过的觉醒门槛推断：≤100 未越过，101–105 越过一次，106–110 两次，111–115 三次，116 起四次。
等级停在 100、105、110、115 时可能已经觉醒，但截图不能证明，按该等级尚未越过门槛计算。
四阶心智费用为 N `60/120/180/300`、R `80/160/240/400`、SR `120/240/360/600`、
SSR `200/400/600/1000`、UR `300/600/900/1500`；物资为心智费用的十倍。
改造按基础稀有度，不以画面升档后的卡框直接计费。

上传原文件限制 5.5 MB，舰船最多 5000 行，Excel 解压内容最多 32 MiB。
WebSocket 仅计算器文件及清单方法允许扩展到 8 MiB，其他业务仍保持 1 MiB。
Excel 文本不执行公式；CSV 导出对公式起始字符加文本前缀。

## 17. 已知限制

自动扫描及截图识别目前支持国服 1280×720 标准船坞，七列位置沿用 AP 标定。
原工具自动采集按 2560×1440 标定，不能直接复用原尺寸参数。
这是原生迁移，未复刻原工具全部特例：无云 OCR、舰种图标判别、原 Excel 截图缩略图和全套多种位移种子选优。
截图批量导入保留各文件条目；自动扫描才核验截图顺序并按位置去重，计算阶段均会按基础身份取最高等级。
识别清单需要逐船核对；自动扫描已用模拟设备验证状态流程，实际账号全船坞准确率需在对应实例验收。

## 18. 示例

拉菲 100 与拉菲.改 106 合并后按 106 级、基础 SR 计费，剩余 `360 + 600 = 960` 心智单元Ⅰ。
125 级不再产生目标 120 级的费用。等级未读到或仍待核对时显示核对状态，不计入总额。
JSON 为带 `ships` 数组的对象或数组；CSV / Excel 按“船名”和“等级”表头定位。
原工具 Excel 的明细第二行表头、存疑状态和右侧排除船名区均可回读。

## 19. 调试方法

运行 `uv run python -m unittest tests.test_mind_calculator tests.test_fleet_ship_names tests.test_api`。
离线夹具覆盖真实船名、META、截断名、等级与核对状态；模拟图覆盖漏百位、第三排、灰色卡面误判、
整屏等级漏检、色带像素偏差、按住期间的连续位移追踪、大倍率小滑块、短距离校正、严格回顶、
三排累计位移、累计取整误差的卡头校准、快拖失去重叠后原位置回退、触控特效避让与短暂遮挡、
持续遮挡退出、动画停稳、同一触点反向过冲校正、末页及无重叠拒绝。
`uv run python -m unittest tests.test_live_drag` 验证五个控制后端保持触点、平滑移动与截图并行、实时反向修正、取消移动及异常释放，不连接真实设备。
`uv run python -m unittest tests.test_scheduler_recovery` 验证识别失败保留具体原因且不重启模拟器。
浏览器流程运行 `npx --prefix frontend playwright test --config frontend/playwright.mind.config.ts`，
模拟服务使用 `dev_tools.mind_calculator_mock.py` 调用真实算法，不连接任何设备。
浏览器回归还覆盖开服检测关闭时启动扫描、草稿保存后解除禁用、扫描停止、地区与运行/更新状态提示。
查看任务日志中的“扫描页”“识别卡片”“船坞位置”，并检查舰船来源中的重读提示。
