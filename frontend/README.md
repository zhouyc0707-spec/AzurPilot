# AzurPilot React 控制台

前端采用 React、TypeScript、Vite 与 React Router。使用「实例和任务导航 → 工作区」两栏布局，采用 Apple 风格的分组布局、系统字体与 Lucide 标准图标，支持移动端折叠菜单。业务通信统一使用 `/api/v1/ws`，不依赖 PyWebIO、Vue 或 Electron。

旧版主题默认进入主页，点击 AzurPilot 标题或图标也可返回。主页由左侧「指挥台」与右侧实例卡片网格组成：指挥台提供问候、实例状态摘要、开源项目入口与「切换旧版界面」快捷键；每张实例卡片显示运行状态、当前任务与连接信息，点击进入以实例名为标题的总览。顶部导航固定，面包屑中实例名右侧的三角按钮用于快速切换实例，并保留当前任务或统计页面；支持方向键、Home/End 和 Escape。任务配置标题旁的放大镜展开搜索框，默认收起；日志搜索与级别筛选也默认收起，通过滑杆图标切换，筛选生效时图标高亮。

系统设置与更新器均为主页下的全局页面，无实例时仍可访问。主题和语言在界面设置中调整，偏好保存在当前浏览器。语言选择沿用五种现有翻译，切换任务菜单、配置字段和说明，控制台固定文案仍为简体中文。实例自动运行与删除操作在实例总览的设置按钮中；旧实例设置链接重定向至全局系统设置。系统设置首张卡片是启动器设置：显示启动器连接状态并开关 Windows 开机自启动，仅在本机访问且由启动器拉起时可用。

更新器展示本地 HEAD、配置分支对应的上游 HEAD、领先/落后数量，以及双方完整可达提交历史。每页 50 条，提交正文可展开。获取更新只获取远程内容，更新按钮复用原有实例停止、依赖同步与监督器重启流程；本地分叉或缺少重启服务时不可应用更新。更新提示显示在顶部导航，点击跳转更新器，无自动弹窗。

配置表单只显示名称和说明，内部路径仍可作为搜索关键词。多行输入位于说明下方并占满宽度，高度随输入内容和自动换行增减，空值或单行只占一行；带 `mode: yaml` 的参数使用按需加载的 CodeMirror 编辑器，提供行号、语法颜色、自动缩进和撤销，颜色随主题切换。

## 换装收藏统计

收藏页打开时自动检查国服完整维护公告，停留期间每五分钟检查一次。首次包括 2026 年 11 月 12 日维护的两名联动角色及两件换装，之后持续追加公告中新出现的角色和换装。后端从 TapTap 官方专区读取正文，按公告中的稀有度、本地舰船资料及必要的 BWIKI 图鉴补齐信息，无法确认的角色显示待补齐并自动重试。公告发布后即可作为未拥有条目收录。

角色名称以原名为标准。国服公告中的和谐名通过图鉴重定向及原名、和谐名字段核验，例如猃对应云仙、花园对应新泽西、鵗对应信浓。匹配到已有原名档案时，新换装关联其原 ID，保留名称和收集记录。新增角色使用核验后的原名，尚未确认的映射进入待补齐名单。

同步按明确别名及规范化名称去重，新增角色收集数量为 0、新换装为未拥有，已有数量、拥有状态和用户填写的获取方式继续保留。新增换装沿用现有自定义目标加一规则。每批追加可在原页面撤销，撤销或删除后保留处理标记，后续轮询不会重复加回。显式导入备份会清除处理标记，下次检查可补入备份之后的新条目。收藏仍保存在浏览器，公告归档位于服务端 `config/skin-collection/announcements.json`。换装公告未给出价格时记录获取方式，钻石金额可在原详情页补填。

实例侧栏的「茗喵证券交易所」下方提供「换装收藏统计」，路由为 `/i/:instance/skin-collection`。页面由 `src/pages/SkinCollection.tsx` 嵌入 `public/skin-collection/index.html` 与本地 `assets/`，保留原收藏页的角色档案、待完成清单、统计、筛选和备份导入导出；无需外网资源或游戏操作。

收藏数据沿用原页面的 `azurLane*` localStorage 键，属于当前浏览器和访问地址，各实例共用，不会上传到脚本服务端或自动同步设备。首次迁移请在原 `index (14).html` 点击「导出备份」，再在内置页点击「导入」，校验预览后确认替换；使用相同浏览器与 WebUI 地址继续访问。清除浏览器数据前应导出备份。自定义图标和查看位置不包含在原有 JSON 备份中。

`InstancePageActivities` 首次进入后保留 iframe，切换页面保留查看与编辑状态；隐藏或销毁前通过 `azurpilot:collection-save` 同步完成原页的防抖保存。切换实例会重建该页并读取同一份收藏记录；已提交的查询与筛选状态按原页面逻辑恢复。静态路径使用相对应用基址，支持带路径前缀的部署。更新内置资源时保留 `assets/vendor/` 中的第三方许可文件。

切换到总览、统计等页面再返回时，通过 `azurpilot:collection-restore` 恢复离开前的页面、获取方式、角色列表、详情和抽屉滚动位置。隐藏及恢复期间冻结位置采样，避免浏览器隐藏 iframe 后返回零坐标覆盖记录；等待布局就绪后只恢复坐标，不重建列表或清除当前输入。快速切页会取消旧恢复回调，用户主动滚动或输入时也会停止尚未完成的恢复。回主页后重新进入则沿用 sessionStorage 中的查看状态。

## 界面材质

旧版浅色主题的仪表盘资源卡片使用纯白底色，卡片外层与内容内层一致；单张卡片和合并卡片共用这一规则。

旧版统计页的体力变化、大世界数据收集、耄耋相接收获、每日经验检测和委托收益统一使用外层卡片。体力变化的标题、时间范围、图例和图表放在同一张卡片内，画布不再单独套圆角边框；浅色主题使用白底，深色主题沿用对应底色。时间范围与图例区域已移除「重置图表」按钮，图表缩放后可双击恢复完整缩放范围。

旧版「大世界数据收集」只显示本月有记录的侵蚀等级，保留 1 → 5 → 3 的相对行序。「本月／历史耄耋相接收获」显示所选月份的 9 列数据，也只显示该月有记录的等级；已有战斗、事件或掉落记录时，即使高价值物品收益全为零，仍保留该行。

「查看历史月份」弹窗同时提供月份跳转和历月累计收获：侵蚀等级、有效战斗轮数总和、平均黄币／金菜／深渊／隐秘每轮收益，四项均值保留 6 位小数。累计值沿用全设备历史 CSV 的口径，由 `statistics.legacy.meowLoot.cumulativeRows` 独立返回，不随所选月份变化，也不受月度空行隐藏影响；无历史月份仍可打开弹窗。历史页保留月份入口，并提供「回到本月」。接口保留原有 14 列定义，前端按列键分开展示；旧响应未提供 `cumulativeRows` 时仍从原有行提取累计列。原 PyWebIO 保留月度布局并同步空行隐藏，历史月份弹窗也提供独立累计表。

## 界面主题

新版遵循上游入口：已有实例时直接打开实例总览，没有实例时进入首次设置向导；标题打开系统设置，侧栏任务分类在原位展开。新版提供实例标签高度、侧栏及总览调度栏拖动调整、调度栏左右切换。旧版保留首页、实例下拉框、桌面向右展开任务菜单及原统计排版。

在「界面设置 → 界面主题」中选择「现代」「简约」或本地「旧版」。现代使用独立 `modern-light` / `modern-dark` 标识承接上游新版；原 `legacy-light` / `legacy-dark` 保留本地布局与统计，顶栏可往返切换并记住新版主题。现代主题支持浅色、深色、普通与玻璃材质，也可以配置主题色和背景。简约主题沿用现有页面布局，使用不透明实色、直角侧栏与顶栏和圆角内容面板，并关闭壁纸、毛玻璃、阴影和装饰动效。

简约主题的「主题模式」支持自动、浅色、深色，以及自带固定配色的程序员、复古灰、复古蓝和复古红。自动模式实时跟随系统外观。自动、浅色和深色支持五套预设主副色，也可以新增、编辑或删除自定义配色。主色用于主要操作、选中态和图表，副色用于辅助信息。偏好保存在当前浏览器，删除当前自定义配色后回到默认配色。

### 表单控件

`src/styles/forms.css` 统一任务配置、系统设置、登录与实例弹窗、统计和日志筛选的表单样式，沿用 `--theme-*` 主题变量。输入控件采用轻边框、圆角、系统蓝焦点环，错误同时显示红色边框与文字提示；开关实际点击区域为 52×44px，移动端输入和选项标签至少高 44px。

`FormControls.tsx` 提供自定义选择器、复选框与可显隐密码输入框。下拉箭头、勾选、密码显隐及保存状态使用 Lucide 图标；选择菜单使用顶层圆角浮层，提供选中勾、方向键导航、文字查找、Enter 确认、Escape 取消及视口边缘避让；数字步进和日期选择保留浏览器原生行为。多行输入继续自动增减高度，YAML 编辑器保留语法高亮与独立滚动。深色、减少动态效果及强制颜色模式共用这些控件。

新增选择器应使用 `Select`，配置字段继续使用 `FieldInput`，避免各页面单独绘制箭头或勾选图标。`e2e/forms.spec.ts` 验证键盘操作、值类型、密码显隐、错误提示和移动端布局，并生成浅色、深色及移动端截图。

配置翻译由 `src/app/configTranslation.ts` 解析普通组名和参数名，并将含小数点的选项键作为完整键读取；例如岛屿额外效率 `0.04` 显示为「4%」，保存值仍为数值 `0.04`。整数零使用翻译键 `0`，避免浏览器把 `0.0` 序列化为 `0` 后丢失文案。缺失翻译继续使用原有名称回退，两族主题共用此逻辑。

## 启动

需要 Python 3.14、uv，以及 Node.js 22.12 或更高版本（推荐 Node.js 24）。在仓库根目录运行：

```powershell
uv sync --frozen
npm ci --prefix frontend
npm run build --prefix frontend
$env:ALAS_WEBUI = "react"
uv run python gui.py --host 127.0.0.1 --port 22267
```

浏览器打开 `http://127.0.0.1:22267`。不指定端口时沿用 `config/deploy.yaml` 的 `WebuiPort`，代码默认值为 25548。首次使用可从默认模板创建实例，再设置模拟器序列号、服务器及需要启用的任务。

界面选择以 `ALAS_WEBUI` 为准：`react` 使用 React，其他非空值（如 `legacy`）使用旧版 PyWebIO。未设置时，手动启动默认使用旧版；由启动器通过信任环境变量拉起，或带 `--electron` 参数启动时，默认使用 React。上述 PowerShell 示例显式选择 React，环境变量仅作用于当前终端及其子进程。

`gui.py` 会检查前端源码摘要，缺少产物或源码变化时重新构建。依赖摘要匹配且构建工具可用时复用 `node_modules`；首次安装或依赖变化时使用 `npm install --no-save --prefer-offline`，优先读取本地缓存并保留仓库的锁文件。安装先尝试 npmmirror，失败或超时后切换 npm 官方源，每次安装最长 600 秒。

已缓存的构建工具缺失、增量安装后仍缺少构建工具，或已有依赖的增量安装在两个源均以错误退出时，才使用 `npm ci` 干净重装。安装和打包分别记录耗时，源码摘要在打包成功后写入。CI 仍使用 `npm ci` 校验干净安装。

仓库锁文件统一使用官方源地址，npm 会按本次指定的 registry 替换下载主机；CI 在安装前检查锁文件，并使用官方源验证安装。

## 开发

后端：

```powershell
$env:ALAS_WEBUI = "react"
uv run python gui.py --host 127.0.0.1 --port 22267
```

另一个终端：

```powershell
cd frontend
npm run dev
```

浏览器打开 `http://127.0.0.1:5173`。Vite 将 WebSocket 代理到 22267；其他端口可设置 `AZURPILOT_BACKEND=http://127.0.0.1:实际端口`。代理保留 Host，使浏览器来源校验仍然有效。

## 独立前端模拟服务

普通界面需要 Node.js 和前端依赖，无需 ADB 或模拟器；舰船数据与调度器算法用例另需项目 Python 环境，模拟服务通过 `uv run --no-sync` 调用隔离的真实算法：

```powershell
npm ci --prefix frontend
npm run dev:mock --prefix frontend
```

打开 `http://127.0.0.1:5173`。此命令同时启动 Vite 和监听 `127.0.0.1:22392` 的 mock server，按 Ctrl+C 一并退出。也可单独运行 `npm run mock --prefix frontend`，另开终端执行 `npm run dev --prefix frontend -- --mode mock`。mock 模式始终代理到模拟服务，不使用 `AZURPILOT_BACKEND`。

若 5173 已被占用，可执行 `npm run dev:mock --prefix frontend -- --port 5175` 更换页面端口。

模拟服务从公开的 `args.json`、`menu.json`、翻译文件和 `template.json` 读取元数据，所有实例、部署设置和日志写入只存在内存，重启即重置；不读取或修改用户配置、不启动游戏进程。它使用真实 WebSocket 信封和生成的参数契约，覆盖实例创建/复制/删除、配置字段合并与校验错误、模拟启停、日志订阅、预览、统计和启动偏好。

默认包含 `demo-main`（正常数据）、`demo-alt`（不同连接与空统计）和 `demo-error`（错误状态与无截图）。预览是 1280×720 的 SVG 测试图；运行中的实例每三秒产生一条日志。此服务用于验证前端交互，真实运行、完整业务校验和安全策略仍以 Python API 测试为准。

可在启动前设置以下环境变量：

| 变量 | 用途 |
| --- | --- |
| `AZURPILOT_MOCK_PORT` | 修改模拟服务端口，默认 22392；Vite 自动使用相同端口 |
| `AZURPILOT_MOCK_PASSWORD` | 设置测试密码，验证登录和重连；默认无需认证 |
| `AZURPILOT_MOCK_SCENARIO=empty` | 从零实例开始，测试欢迎页和首次创建 |

浏览器刷新保留本次模拟服务的数据。两个标签页可直接保存各自修改的字段，无关字段互不覆盖；同字段按服务端接收顺序写入。输入立即提交，断线时保留草稿并在重连后自动保存；格式错误保留输入并在字段下方提示。

## 目录职责

| 目录 | 职责 |
| --- | --- |
| `src/api/client.ts` | 连接、认证、心跳、请求关联、超时和重连 |
| `src/api/generated.ts` | 从 Python 模型生成的方法参数类型 |
| `src/api/contract.json` | 版本化参数 JSON Schema |
| `src/api/types.ts` | 响应数据及页面领域类型 |
| `src/config` | 跨页面字段保存队列、草稿恢复、重试与数值输入校验 |
| `src/app` | 应用布局、连接状态、共享元数据 |
| `src/components` | 可复用表单、弹窗、空状态等 |
| `src/pages` | 总览、配置、分类统计和系统设置 |
| `src/styles` | 设计变量、布局、组件样式 |
| `e2e` | 连接真实测试 API 的浏览器回归 |
| `mock` | 独立的内存模拟服务及状态测试 |
| `../module/api` | 协议、认证会话、路由和业务适配 |
| `../module/runtime` | 独立于界面的进程、OCR、更新与认证服务 |

配置表单直接读取已有 `args.json`、`menu.json` 和中文翻译，覆盖全部任务菜单；无需在 React 中重复登记游戏配置。字段支持字符串、数值、范围、开关、日期、多选、选项和任务优先级。隐藏字段不展示，固定字段禁止经 API 修改。存储空间沿用旧版行为：空字典时隐藏字段、空分组和导航；有状态时展示完整格式化 JSON，可点击清除按钮重置为空字典，不能任意改写状态内容。

## 迁移边界

- `gui.py` 保留原有父监督器、依赖同步、双栈监听与工作进程回收；选择 React 时使用 `module.api.app:create_app`，选择旧版时使用 `module.webui.app:app`。
- `module/webui`、`webapp` 与 PyWebIO 仍用于旧版界面及其定制，不能按迁移残留删除。两套界面共用 `module/runtime` 的运行服务；React 页面使用 `frontend/` 与 `module/api`，不依赖旧版页面的渲染流程。
- JSON 配置、YAML 参数生成流程、现有调度器和 `/mcp` 挂载保持兼容。独立 MCP 使用迁移后的运行服务。
- 总览右侧支持日志/截图切换。预览订阅底层实际截图，所有截图方案共用统一发布入口；每张新截图触发更新，空闲保留最后画面，不产生额外截图请求。旧日志链接重定向到总览。
- 统计页按资源趋势、大世界趋势、大世界总结、委托收益、舰船经验、短猫掉落分类，复用旧统计源及计算口径。提供折线、K 线、时间过滤、缩放、十字游标、原始明细与 CSV 导出；旧统计 HTML/JavaScript 无需加载。
- 服务端部署设置重启后生效；浏览器主题即时生效。密码不会由设置接口返回，填写空密码表示保留。

协议详情见 [API.md](API.md)，架构总览与迁移边界见 [WebUI 总览](../docs/modules/webui/index.md)。增加方法时先定义后端参数模型和路由，再生成契约，更新响应类型与对应测试；不得通过方法名反射任意 Python 属性。

## 总览与统计交互

- 任务计划中的待运行／等待中任务可点击「执行一次」，使用现有配置单独运行，结束后不执行其他任务；运行期间按钮变为「停止」，再次点击立即停止并回到原队列。中途取消保留原排程，正常完成采用任务算出的下次运行时间。新旧主题、总览和配置页共用这个入口；同一实例已有任务运行时，其他启动按钮不可用，设置入口仍可使用。

- 总览资源支持全部 12 种资源自由选择、调整顺序和恢复默认；卡片自动换行并填满空间，搭配按实例保存在当前浏览器。
- 任务计划展示全部任务，明确区分运行中、待执行、等待中。右侧日志包含搜索、级别筛选、暂停自动滚动、清空当前视图及导出，切换截图后保留日志条件。日志数据在进入 React 状态前最多保留最近 1000 条，避免异常大的历史 payload 在 WebView2 中创建数万 DOM 节点并阻塞交互；正常后端仍只下发约 400 条。
- 心情等只读日期沿用旧版文本显示，保留历史记录的小数秒；可编辑日期仍使用日期控件。
- 访问密码在首次成功登录后记忆于当前浏览器，刷新和重开页面自动登录；修改密码后旧值会失效。
- 图表按需加载 [Apache ECharts](https://echarts.apache.org/handbook/en/concepts/axis/)，支持滑块、Ctrl + 滚轮、框选缩放和图像导出。放大查看后可按 Escape 收起。
- 大世界和委托支持历史月份；今日、本周委托以当前日期为准。短猫掉落保留旧版全设备累计统计，刷新统计会重算已有本地掉落记录。界面说明标注估算、聚合与缺失值口径。

## 舰船数据与共享船坞

舰队管理中的「舰船数据」提供舰队科技、养成计算、扫描更新和我的舰船四个页签；智能换船单独整合舰队信息、换船配置、换船调度和换船装备。旧 `task/MindCalculator`、`mind-calculator` 和 `task/FleetTechnology` 链接跳转到相应分析标签；旧扫描任务不再显示在工具菜单。

`dock.report({instance})` 返回共享扫描报告（`revision`、`updated_at`、`min_level`、`max_level`、`ships`、`complete`、`review_count`、`source`、`scan_range`）。`dock.configure({instance,min_level,max_level})` 保存 1–125 级范围并返回报告；点击统一扫描入口才调用 `tasks.run({instance,task:"DockScan"})`。扫描读取船坞舰名和等级，需要导航与滚动，不进行升级、突破、觉醒或换船。页面展示扫描时间、实际快照范围 `scan_range`、数据来源、完成情况与待核对数量；`min_level`/`max_level` 是下一次扫描设置，修改设置不会伪装成已扫描数据。

舰船编辑通过 `dock.patch` 保存；文件和截图由 `mind.import` / `mind.recognize` 解析，再通过 `dock.stageImport` 与 `dock.review` 暂存及确认。养成计算通过 `mind.plan` 只读计算，科技里程碑使用 `fleetTech.patch` 独立编辑。用户已确认采用新流程，旧记录仅留存备查，不继续提供旧排除与导出行为。页面浏览不触发游戏任务；旧版主题、喵语及扫描失败保护继续保留。详细行为见[舰船数据](../docs/modules/webui/fleet-analysis.md)。

「扫描更新」页的「导出舰船 JSON」按钮会重新读取 `dock.report`，下载 `<实例名>-ships-<导出时间>.json`。文件包含 `version: 1`、`exported_at` 及完整报告：`ships` 只包含已保存的舰船，保留独立卡片 ID、未知经验、满星/改造状态和识别待核对标记；`pending_changes`、`pending_revision`、`pending_read` 单独保留候选差异和读取摘要。导出用于备份和离线核对，不修改数据库、不确认候选差异，也不启动游戏任务。此完整报告与「导入舰船清单」的精简字段格式不同，不能直接用于该导入入口。
